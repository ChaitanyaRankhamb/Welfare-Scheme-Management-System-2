Chaitu, let's turn this into a reusable Nginx Local HTTPS Certificate Setup Guide for your YojanaConnect project. You can save it in your repository and follow the same steps whenever you need to set up HTTPS for another local project.

One important distinction: these files enable HTTPS; the HTTP-to-HTTPS redirect itself is configured in your Nginx configuration.

# Nginx HTTPS Certificate Guide

## 1. Understand the seven files

Assuming you generated the files using the commands we've discussed, your `nginx/ssl/` directory contains these files:

| File            | Purpose                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| `rootCA.key`    | Root CA private key. Signs server certificates. Keep it secret.               |
| `rootCA.crt`    | Root CA certificate. Install it into your local machine's trusted root store. |
| `rootCA.srl`    | Serial-number tracking file used by OpenSSL when issuing certificates.        |
| `localhost.key` | Private key that Nginx uses for the localhost HTTPS connection.               |
| `localhost.csr` | Certificate signing request containing the requested server identity.         |
| `localhost.ext` | Configuration defining SANs and other certificate extensions.                 |
| `localhost.crt` | Signed server certificate that Nginx presents to the browser.                 |

The relationship is:

Root CA

`rootCA.key` + `rootCA.crt`

Signs and establishes trust in server certificates

Server certificate creation

`localhost.key` + `localhost.csr` + `localhost.ext`

Issued certificate

`localhost.crt` + `localhost.key`

Configured in Nginx for HTTPS

## 2. Generate all seven files

Run these commands from your project's `nginx\ssl` directory in Windows CMD, where OpenSSL is available.

### Step 1 — Generate the Root CA private key

cmd

```
openssl genrsa -out rootCA.key 4096
```

Creates `rootCA.key`. This is the secret key used to sign server certificates.

### Step 2 — Generate the Root CA certificate

cmd

```
openssl req -x509 -new -nodes -key rootCA.key -sha256 -days 1825 -out rootCA.crt -subj "/CN=MyProject Local Root CA"
```

Creates a self-signed CA certificate valid for approximately five years.

### Step 3 — Generate the localhost private key

cmd

```
openssl genrsa -out localhost.key 2048
```

Creates the private key Nginx uses for its localhost certificate.

### Step 4 — Create the certificate signing request

cmd

```
openssl req -new -key localhost.key -out localhost.csr -subj "/CN=localhost"
```

Creates a CSR requesting a certificate for `localhost`.

### Step 5 — Create `localhost.ext`

Create a text file named `localhost.ext` in the same directory, with this content:

```
authorityKeyIdentifier=keyid,issuer
basicConstraints=CA:FALSE
keyUsage=digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=@alt_names

[alt_names]
DNS.1=localhost
IP.1=127.0.0.1
IP.2=::1
```

This configures the certificate's Subject Alternative Names (SANs), allowing it to cover `localhost` and the local loopback IP addresses.

### Step 6 — Sign the localhost certificate

cmd

```
openssl x509 -req -in localhost.csr -CA rootCA.crt -CAkey rootCA.key -CAcreateserial -out localhost.crt -days 365 -sha256 -extfile localhost.ext
```

Creates two files:

* `localhost.crt` — the signed server certificate.

* `rootCA.srl` — OpenSSL's CA serial-number file, created if it doesn't already exist.

The certificate is valid for 365 days.

### Step 7 — Verify the certificate

cmd

```
openssl verify -CAfile rootCA.crt -purpose sslserver -verify_hostname localhost localhost.crt
```

Expected result:

```
localhost.crt: OK
```

## 3. Trust your Root CA on Windows

If you have not already installed this new Root CA, open CMD as Administrator in the `nginx\ssl` directory and run:

cmd

```
certutil -addstore -f Root rootCA.crt
```

This installs the CA certificate into the Windows Trusted Root Certification Authorities store. Only trust CA certificates you created and control.

## 4. Configure Nginx to use the certificate

In your Nginx HTTPS server block:

Nginx

```
server {
    listen 443 ssl;
    server_name localhost;

    ssl_certificate     C:/welfare-scheme-management-system/nginx/ssl/localhost.crt;
    ssl_certificate_key C:/welfare-scheme-management-system/nginx/ssl/localhost.key;

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

Adjust the paths and upstream port to match your actual setup.

To redirect HTTP to HTTPS, configure a separate server block:

Nginx

```
server {
    listen 80;
    server_name localhost;

    return 301 https://$host$request_uri;
}
```

Validate and reload Nginx after configuring both blocks.

## 5. Important security practices

* Never commit `rootCA.key` or `localhost.key` to Git.

* Add private keys and local certificates to `.gitignore` if they reside in the project directory.

* For better isolation, keep the Root CA private key outside the application repository.

* For public production domains, use a trusted public CA such as Let's Encrypt rather than your local development CA.

* If you create another project, you can reuse an existing development CA if you control its private key and it remains valid. You don't need a new CA for every project.

Remember: The Root CA establishes trust; the localhost certificate identifies your development server; Nginx uses the localhost certificate and key to serve HTTPS; and the HTTP redirect sends users to the secure URL.
